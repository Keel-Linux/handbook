goes through a pull request.

## Finding: the release is not cumulative

`keel-channel set` names only the layers that the release directory
stages. `keel-publish-mirror` replaces the flat layer files of those
layers only. Release 2026-11-10 stages 8 layers. The layers ntfy, mariadb
and redis of the earlier releases are not in it. After the publication:

- the `stable` pointer does not name ntfy, so `keel pull ntfy` gives 404;
- the flat manifests of ntfy, mariadb and redis name parents (the earlier
  web and core layers) that the flat tree does not hold.

The 16 images of this release are not affected. A machine that was
installed from an earlier image is not affected: it gets packages from
the archive. The CI job `tests / appliance` of keel-ntfy, keel-mariadb and
keel-redis fails until a release that holds these layers is published.
The job is correct and stays as it is.

Corrective action: the next release (mariadb 19.0-12, redis 19.0-13, ntfy
19.0-6, after their commissioning and the approval of the maintainer)
must stage each layer that the channel must keep. Follow-up for the
tooling: `keel-channel set` and `keel-publish-mirror` must keep the
layers of the release before, or refuse a release that drops a layer or
leaves a flat layer with a parent that is gone.
