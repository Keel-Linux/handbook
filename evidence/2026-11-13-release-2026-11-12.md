operator copied the layer sets of mariadb, redis and postgresql of release
2026-11-11 by hand into `/srv/keel-release/2026-11-12`. The sha256 of
each of the 3 tarballs in the MANIFEST is the sha256 of release
2026-11-11. This is the same workaround as in release 2026-11-11, not an
approved procedure.

MANIFEST lists every file of the directory. Before the signing, the
operator moved the files of nextcloud and nodebb out of the directory to
`held-2026-11-12` on the build host. The MANIFEST of release 2026-11-12
names no nextcloud or nodebb file.

These items are to file. None has a number yet, except apt#112.

- The release tool does not make a cumulative release (apt#112). This
  release needed the copy by hand of 3 layer sets.
- The operator changed the pool `stable-5` with a script of the round. A
  tool of `Keel-Linux/apt` must add a package from snapshot.debian.org to
  a pool, and check it against the signed index.
- `systemd-machine-id-commit.service` failed on a BR2 replica in 2 cloud
  runs. On a plain container on BR2 it was still `activating` on 3 boots of
  6. The cause is not known.
- The ntfy ISO on BR1 showed `SQUASHFS error` lines at the first boot, and
  the Laravel cloud_advanced primary stopped in keel-init. Each passed on a
  second run. The cause of each is not known.
- `bt-aplinfo` reads `/turnkey/fab-keel/products`, not the products tree of
  the round. It gave a wrong changelog version for 6 applications.
- With `--no-index`, the commissioning gate does not check the templates at
  signing.
- `keel-publish-mirror`, when started on the build host, says "no release
  2026-11-12 on the build host" after an ssh failure. The text must name
  the real cause.
- The channel pointer is not signed again after the publication. The
  `stable` pointer was signed 5 min before the publication.
- No package installs the channel keyring, so `keel pull --channel` on a
  stock node fails with exit 18 (decision 0016).
- The 7 application pages show the revision before. They need a new run
  of `keel-app-page` with the records of this round. A new run of the
  ntfy page puts back the colon of the lead (follow-up of release
  2026-11-11).
- The pull check reads only the applications of the release. It must also
  pull the layers that were copied by hand.
