Date: 2026-11-01. The time zone is UTC. No secret is in this file.

writes, a connect timeout of 3 s and `timeout 15`. An id counts as
acknowledged only when the client returned 0.

A round: `pkill -9 -x mariadbd` on the holder. A script on the holder ran
`keel database follow` when the server answered, which is the worst case. The

## What went wrong in the test

These are errors of the test, not defects of the product.

- **The first writer unit counted nothing.** `systemd-run` gave it no `HOME`,
  so the client did not read `/root/.my.cnf` and failed with a TLS error. It
  acknowledged no write. The unit started again with `HOME=/root`, before the
  planned promotes.
- **`keel diff` on W returned 13 at the end.** The `/root/.my.cnf` of the test
  made the local `mariadb` client use the test account, so keel could not read
  the server. With the file removed, `keel diff` on W returned 0 with 0 drift.
- **A status command stopped responding once.** It read
  `/var/log/inithooks.log`, which holds console output, through `pct exec`. The
  check ran again with a timeout. Nothing on the CTs changed.
- **A setup command included `rm -f /dev/null`, by mistake, on the workstation.**
  It ran as a normal user and failed. `/dev/null` is unchanged, and the command
  did not run on a test host.
- **No round was rejected.** The driver ran 12 rounds, and all 12 are in the
  table.

## What this test does not show

- The upgrade was on CTs with no pair yet. A live pair that goes from 0.23.62
  to 0.23.68 was not tested.
- The changelog of keel puts these fixes after 0.23.68, so this test did not
  use them: keel#110 (0.23.69), keel#191 (0.23.70) and keel#107 (0.23.71).
- The test used the MariaDB layer only. WordPress was not on this pair.
- The test cut one node at a time. BR3-THIN was not used.
- The client of the writer used `skip-ssl-verify-server-cert`. The writer did
  not check the certificate of the VIP. The replication channel did check its
  certificate, as the table in "Result" shows.
- A client of a cut node can wait for its own timeout. The writer used
  `timeout 15`, so a hung client did not stop the test.
