- `keel mesh invite` + `keel mesh join` on test60-c (BR2, cross-site): OK

### VIP and MariaDB pair

- `keel vip promote` on test60-a: epoch 1, VIP carried on wg0

### Upgrade safety check (keel#138)

- `keel mesh upgrade-check` on replica (test60-c): PASS
  - "every other etcd member is healthy and none restarts"
- `keel mesh upgrade-check` on primary (test60-a): PASS

  - "every other etcd member is healthy and none restarts"

## Defect found

MariaDB `bind-address` written by `keel spec apply --system` does not
include the node's own overlay address (only localhost and the VIP).
`keel database follow` on the peer connects to the node's overlay
address on port 3306, which is not bound. Workaround: manually add
the overlay address to `99-keel-database.cnf` and restart MariaDB.
This should be filed as a defect (the cnf writer should bind the
overlay address alongside the VIP).

## Conclusion

keel 0.23.60 passes the real-node test on a 3-node cross-site mesh
(BR1 + BR2). All fixes from the merged PRs (#136, #141, #142, #145)
work as intended:

- Mesh, etcd, VIP, replication: functional
- Planned failover and failback: functional
- VIP survives restart: confirmed (keel#87)
- Upgrade check: functional (keel#138)
- One new defect: bind-address missing overlay address
